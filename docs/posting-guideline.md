# 投稿ガイドライン（ライズ・ナレッジ）

対象：記事やコメントを書く、ソリューション事業部のみなさん。

> **学びを、仲間の武器にする！**
> 現場で得た知見は、離れて働く仲間にとって大きな力になります。うまくいったことも、ハマったことも、気軽に共有しましょう。

## 書いてほしいこと

- 現場で役立った手順・Tips、トラブルとその解決方法
- 設計や考え方、勉強会・資格の学び
- 常駐先での働き方の工夫、コミュニケーションのコツ、キャリアのこと

完璧な記事でなくてかまいません。短いメモでも、誰かの時間を大きく救うことがあります。

## 書いてはいけないこと

ライズ・ナレッジは社内限定ですが、記事は事業部の全員が読みます。客先との約束（秘密保持）を守るため、次のことは書かないでください。

| 書かないこと | 例 | 代わりに |
|---|---|---|
| 客先の名前・案件名・客先の人名 | 「A 社の〇〇システム」 | 「金融系のお客様」「ある Web サービス」 |
| 客先が推測できる固有名詞 | 社内システムの名前、独自の略語 | 一般的な言葉に言い換える |
| 認証情報 | パスワード、API キー、トークン、秘密鍵 | `****`、`<password>`、`${API_KEY}` |
| 内部の識別子 | 実際の IP アドレス、ホスト名、内部 URL、アカウント ID | `192.0.2.10`、`example.com`、`web01.example` |
| 個人情報 | 実在の人の連絡先・社員番号 | 書かない |
| 社外秘の情報 | 契約内容、金額、未公開の計画 | 書かない |
| 人や会社への批判・不適切な表現 | 客先・他社・個人の悪口 | 事実と学びだけを書く |

スクリーンショットにも注意してください。画面の端に客先名や URL が写っていないか、貼る前に確認しましょう。

## 公開までの流れ

1. **下書き**：書いている間は自動で保存されます。あなたにしか見えません
2. **レビュー申請**：大分類（開発・インフラ・キャリア・働き方）を選んで申請します
   - パスワードや秘密鍵のような文字列があると、申請の時点で止まります。表示された行を直してください
3. **AI チェック**：機密情報や不適切な表現がないかを AI が確認します。問題が大きいと自動で差し戻されます
4. **管理者の確認**：管理者が読んで、公開するか判断します。差し戻されたときは理由が届くので、直して再申請してください
5. **公開**：事業部の全員が読めるようになります。公開後に直すと、新しい版として審査し直します（その間は元の版が表示されます）

## 分類の選び方

- **大分類**（1 つ）：記事の分野です。あなたの所属部署ではなく、内容で選んでください
- **属性**（いくつでも）：記事の種類、工程、言語、製品などです。読む人が絞り込むときに使います
- **タグ**（5 個まで）：製品名・ライブラリ名など、細かいキーワードを自由に付けます

## イニシャルで投稿する

名前を出すのに抵抗がある記事は、「著者名をイニシャルで表示する」を選べます（先に「設定」でイニシャルを登録してください）。

- ほかの人には、名前の代わりにイニシャルが表示されます。ユーザーページやランキングにも、あなたの名前とひもづけて出ません
- ただし、管理者（レビュー画面・監査ログ）には実名が表示されます。社内で完全に匿名になるわけではありません
- 部署名と投稿日は表示されるので、人数の少ない部署では推測されることがあります

## コメント

- 感想・補足・質問など、気軽にどうぞ。Markdown が使えます
- コメントも AI がチェックします。問題が大きいものは投稿できず、判断に迷うものは管理者が確認します
- 自分のコメントは削除できます

## いいね・ストック

- **いいね**：役に立った記事に押しましょう。月間ランキングと月間ベストの参考になります（自分の記事には押せません）
- **ストック**：あとで読みたい記事を保存できます（ほかの人には見えません）

困ったことや、このガイドラインで判断に迷うことがあれば、管理者に相談してください。
