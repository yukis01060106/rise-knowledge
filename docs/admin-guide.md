# 管理者ガイド（ライズ・ナレッジ）

対象：記事の公開を判断する管理者。管理画面は右のメニューの「管理」から開けます。

## 管理者の役割

- **記事を公開してよいか、最終的に判断するのは管理者です。** AI のチェックは手助けで、AI が記事を公開することはありません
- 自分の記事は承認・差し戻しできません。ほかの管理者に依頼してください（管理者は 2 人以上にしてください）
- 管理者の操作（承認・差し戻し・非公開・ロール変更・表彰など）はすべて監査ログに残り、あとから変更・削除できません

## 記事の流れ

```
下書き → レビュー申請 → AI チェック → 管理者の確認 → 公開
                            │               │
                            └──→ 差し戻し ←─┘（著者が直して再申請）
```

- レビュー申請のとき、パスワード・API キー・秘密鍵などが含まれていると、申請そのものが止まります（事前スキャン）
- AI チェックでリスク「高」と判定されたものは、自動で差し戻されます
- AI チェックに 3 回失敗したものは「AI チェック未実施」の印が付いて、管理者の確認に回ります。特に注意して読んでください
- 公開済みの記事を著者が直すと、新しい版として審査し直します。承認されるまでは、元の版が公開されたままです

## レビューのしかた（管理 → レビュー待ち）

1. 申請の古い順に並んでいます。新規か更新か、リスク（高・中・低）、AI チェック未実施かが分かります
2. レビュー画面で次を確認します
   - **AI チェック**：要約・指摘（何行目に何があるか）・修正案。「指摘箇所を本文で確認する」で該当行を強調表示できます
   - **事前スキャンの警告**：IP アドレス・メールアドレス・電話番号・社内ホスト名など（値は記録していません）
   - **差分**：公開中の版から何が変わったか。差し戻した版の再申請なら「前回差し戻した版からの修正」も出ます
   - **本文**：公開されたときの見た目
3. 判断します
   - **承認して公開**：すぐに公開され、著者に通知されます（Slack を設定していれば、タイトルと URL が流れます）
   - **差し戻す**：理由は必須です。著者に表示されるので、どこをどう直せばよいかを具体的に書いてください

### 確認のポイント

- 客先名・案件名・客先の人名、客先が推測できる表現がないか
- IP アドレス・ホスト名・内部 URL・アカウント ID・認証情報が残っていないか
- 画像（スクリーンショット）に社外秘の情報が写っていないか
- 他社・個人への批判や不適切な表現がないか
- 分類（大分類・属性）が内容に合っているか

## 公開後の問題への対応（管理 → 記事管理）

- **緊急非公開**：公開中の記事に問題が見つかったら、理由を入力して非公開にします。すぐにほかの人から見えなくなり、
  著者には理由が表示されます。著者本人の管理者でも非公開にはできます
- **再公開**：理由を入力して再公開します。著者本人の管理者は再公開できません
- **版の履歴**：過去の版と差分、審査の記録（いつ・誰が・何をしたか）を確認できます

## 要確認コメント（管理 → 要確認コメント）

AI チェックでリスク「中」と判定されたコメント、または AI チェックに失敗したコメントです。表示されたまま確認待ちになっています。

- **問題なし**：確認待ちの印を外します
- **削除する**：コメントを削除します（監査ログに残ります）

リスク「高」のコメントは、そもそも投稿されません。

## 月間ベスト（管理 → 月間ベスト）

その月の「いいね」ランキングから 1 本を選んで表彰します。1 か月に 1 本です。表彰した記事にはバッジが付き、
トップに表示され、著者に通知されます。ひとこと（選んだ理由）を添えると、トップにも表示されます。

## ダッシュボード（管理 → ダッシュボード）

レビュー待ちの件数、今月の公開数、レビューの平均時間（申請から判断まで）、AI の自動差し戻し率と未実施の割合、
部署別の月別公開数が見られます。レビュー待ちが溜まっていないか、定期的に確認してください。

## ユーザー管理（管理 → ユーザー管理）

- **ロール変更**：メンバーを管理者にする／管理者をメンバーに戻す。自分自身のロールは変更できません
- **無効化**：退職・異動などで利用を止めるとき。その場でログアウトさせます

## 監査ログ（管理 → 監査ログ）

操作の種類・操作者・記事・期間で絞り込めます。閲覧のみで、変更・削除はできません（DB の権限とトリガーで止めています）。
