# 記事の分類

## 考え方

記事は 3 段で分類する。1 本の深い階層（例：開発 > テスト > Java）にはしない。
「工程」と「言語」のように軸が違うものを 1 本の木にすると、書く人が置き場所に迷い、
同じ内容の記事が人によって別の場所に入り、「Java の記事を全部見る」ことが難しくなるため。

| 段 | 選び方 | 目的 |
|---|---|---|
| 大分類 | 記事ごとに 1 つ（申請に必須）。書いた人の部署とは別 | 大まかな分野で探す |
| 軸ごとの属性 | 管理者が用意した選択肢から選ぶ（任意・複数） | 軸をかけ合わせて絞り込む。表記揺れを防ぐ |
| 自由タグ | 自由に入力（5 個まで） | 製品名・ライブラリ名などの細かいキーワード |

一覧の絞り込みでは、**同じ軸の中は「どれか」、軸どうしは「すべて」** を満たす記事を出す
（例：言語が Java か Python で、かつ工程がテスト）。

## 定義

定義の本体は `src/lib/taxonomy.ts`。DB には「軸のキー:選択肢のキー」（例：`dev.lang:java`）だけを保存する。

| 大分類 | 軸 |
|---|---|
| （共通） | 記事の種類：手順・Tips / トラブル解決 / 設計・考え方 / 学び・勉強会 / 資格 |
| 開発 | 工程（要件定義〜保守・運用）、言語（Java、C#、Python、JS/TS、PHP、Go、Ruby、Kotlin、Swift、COBOL、SQL、その他）、領域（フロントエンド、バックエンド、モバイル、データ・AI、開発環境・ツール） |
| インフラ | 領域（サーバー・OS、ネットワーク、クラウド、DB、セキュリティ、監視・運用、コンテナ・仮想化）、製品・サービス（AWS、Azure、Google Cloud、Linux、Windows Server、VMware、Cisco、その他）、工程（設計・構築・移行・運用保守） |
| キャリア・働き方 | テーマ（常駐先での働き方、コミュニケーション、キャリア、新人・若手向け、リーダー・マネジメント） |

## 運用のルール

- キーは一度使ったら変えない（表示名は変えてよい）。選択肢をやめるときは `hidden: true` にして残す
  （過去の記事の属性を表示できるように）
- 大分類と属性は審査の対象。審査に出した版では変更できない（DB のトリガーで止める）
- 選択肢の追加・変更はコードの変更で行う（デプロイが必要）。運用して頻繁に変える必要が出たら、
  管理画面で編集できるようにする（そのときは DB のテーブルに移す）
- 分類の導入前に書かれた版は、著者の部署を大分類にしてある（属性は空）
- 操作デモ（`demo/`）は `npm run demo:build` でこの定義を `demo/taxonomy.json` に書き出して使う
